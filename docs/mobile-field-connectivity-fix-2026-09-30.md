# Получение заявок и индикация связи на телефоне

Дата: 30 сентября 2026 года. Мобильная версия: 0.1.45, Android versionCode 46.

## Подтверждённые причины

Приложение сравнивало только `isConnected`. При переключении Wi-Fi → 4G → Wi-Fi это значение может оставаться `true`, хотя локальный сервер доступен только по Wi-Fi. Поэтому не запускались ни новая проверка сервера, ни восстановление синхронизации. Кроме того, кэш health-проверки сохранялся при смене сети, а после возврата из фона приложение не запрашивало свежий сетевой снимок.

Получение данных без push запускалось раз в пять минут. Загрузка, отменённая обновлением сессии того же сотрудника, завершалась ошибкой без повторного получения актуального снимка. Это воспроизведено тестами; принадлежность конкретной недоставленной заявки на сервере по представленным скриншотам не установлена.

## Исправления

- Смена типа сети, IP-адреса, подсети или доступного имени Wi-Fi запускает проверку сервера и восстановление синхронизации. Изменение уровня сигнала не запускает повторные запросы.
- При смене сети сбрасывается кэш health-проверки. Индикатор показывает проверку связи, а затем результат свежего запроса. Ответ прежнего подключения не может восстановить зелёный статус.
- При возврате в приложение заново читается состояние сети. Позднее чтение не перезаписывает более новое сетевое событие.
- В открытом приложении цикл получения данных запускается каждые 30 секунд. Периодический цикл не запускается в фоне или при известном отсутствии сети. Это интервал запуска проверки, а не гарантия времени доставки при медленной сети или неуспешной авторизации.
- Отменённая загрузка повторяется один раз для того же сотрудника и контура с актуальным контекстом сессии. Ответ другого аккаунта по-прежнему отклоняется; локальные данные не заменяются чужим снимком.
- Сообщение `StaleAuthResponseError` переведено на русский. Старый текст, уже записанный в локальную очередь предыдущей версией, может оставаться до успешной отправки или обновления ошибки.

Существующие проверки запрещают сохранение ответа прежнего аккаунта и отправку его операции с токеном нового пользователя.

## Ограничения проверки

Локальный сервер ответил на `/api/v1/mobile/health`: `status: ok`, `syncProtocolVersion: 1.0`, `contourId: patrol360-local-enterprise`. Это проверка с компьютера, она не доказывает доступность сервера с телефона.

Чтение Docker-журнала API дважды не прошло автоматическую проверку разрешения: проверка завершилась по тайм-ауту. Содержимое журнала недоступно, конкретная заявка за 30 сентября не сверена. `adb devices -l` не обнаружил подключённых телефонов; установленный APK и реальные переходы Wi-Fi на устройстве ещё не проверены.

## Повторный эксплуатационный тест

1. Установить новую сборку поверх текущего приложения, сохранив локальные данные.
2. При включённом Wi-Fi дождаться результата проверки связи, затем выключить Wi-Fi с оставленной мобильной сетью. Для локального сервера ожидается недоступность сервера, даже если Интернет по 4G работает.
3. Включить Wi-Fi: дождаться проверки и статуса связи без перезапуска приложения.
4. Отправить сотруднику новую действующую заявку и оставить приложение открытым. Проверить появление заявки после очередного цикла получения данных; сверить номер заявки и сотрудника на сервере и телефоне.
5. Повторить смену сети в фоне и вернуться в приложение. Проверить состояние связи и сохранность очереди операций.
