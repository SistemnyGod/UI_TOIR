# Выбор заявок и завершение отправки: реализация и проверки

Дата: 22 сентября 2026.

## Изменения

- `patrolEntryService` перечитывает назначение, последовательно принимает и запускает новую заявку. Повтор после успешного принятия выполняет только запуск. Повторные вызовы одного запуска объединяются.
- Принятие больше не выбирает текущий маршрут. Выбор фиксируется после запуска или явного продолжения. NFC, QR и список точек выбираются по политике маршрута.
- Обработчик используется в карточке заявки, карточке текущего обхода и на главной. Переключение в рамках выбранного сотрудника использует существующую атомарную операцию. Для другого сотрудника действует обычная проверка запуска; чужой выполняемый обход не приостанавливается автоматически.
- Старый адрес переключения ведёт в общий список заявок. В нём доступны имя, маршрут, время и фильтр «Незавершённые». Открытие списка очищает текущую заявку условно, с сохранением исполнителя, результатов и состояния обхода.
- Контроллер черновика точки владеет таймером и последовательными записями. Последние значения фиксируются непосредственно при вводе. Переход с формы задерживается до сохранения; ошибка оставляет форму открытой. Перед камерой выполняется сохранение. Финальное сохранение блокирует поздние записи. Причина ручного осмотра также сохраняется.
- Доставка проверяется по квитанции завершения и файлам из команды отчёта. Автоматический переход возможен только для актуального видимого экрана отправки; история не выполняет его. Условное очищение SQLite учитывает владельца, контур, поколение сессии и ожидаемую заявку.
- Восстановление после авторизации использует сохранённую текущую заявку. Пустой выбор ведёт к списку, выполняемый обход — к прохождению, ожидающий доставки — к итогу, пауза — к карточке с явным продолжением. Переход из уведомления сохраняет приоритет.
- Фильтр «Требуют внимания» получает причины из той же проверки, что и сводка отчёта. Полностью оформленные неисправность, ручной осмотр и разрешённый пропуск не блокируют завершение. Общие ошибки снимка показаны отдельно от точек.

Новые API и серверные миграции для этих изменений не добавлены. Используются существующие операции и квитанции. Разрешение конфликта отмены и история переписки не реализовывались в этом этапе.

## Выполненные проверки

- Полный `npm run verify`: 100 тестов Node и 117 тестов Vitest; TypeScript, проверка кодировки и линтер прошли.
- Новые поведенческие проверки охватывают повтор запуска после принятия, двойное нажатие, проверку сотрудника, последнее изменение перед flush, ошибку записи, завершение при ожидающем автосохранении, готовность точек.
- Проверки навигационного сервиса используют SQLite в памяти и фактический репозиторий контекста. Проверены сохранение исполнителя Б после выхода, отсутствие возврата к А, поздняя квитанция другого обхода, потеря фокуса во время чтения, ожидание файлов, устаревшая сессия, восстановление ожидания отправки и паузы. Это проверки сервисов, а не прохождение экранов на устройстве.
- Серверные интеграции: `MobileAppDbIntegrationTests`, `PATROL360_RUN_DB_INTEGRATION=true`; 8 прошли, 0 пропущено. Использован изолированный контейнер PostgreSQL `patrol360-ppe-test-20260913`, порт 55439, временные базы тестового fixture. Рабочая БД не использовалась. Первый запуск не прошёл авторизацию тестового окружения; повтор с корректным пользователем прошёл.
- Логи: `.codex-tmp/mobile-selection-verify.log` и `.codex-tmp/mobile-selection-db-tests.log`.

## Приёмка, которая остаётся

`adb devices -l` не обнаружил устройств. Поэтому не выполнены:

- два телефона общего аккаунта и полный пользовательский путь А → Б → отправка → список → перезапуск;
- реальное NFC, камера, фотографии и офлайн-перезапуск;
- системная кнопка «Назад», жесты, клавиатура и увеличенный шрифт в собранном приложении;
- визуальное сравнение экранов с макетами, установка обновления и ограниченный пилот.

Навигационные хуки и формы проверены типизацией, а контроллеры — управляемыми задержками и таймерами. Это не заменяет проверку React Native экранов на устройстве. Сохранение при мгновенном завершении процесса во время незавершённой SQLite-записи не гарантируется.

Рабочее развёртывание не выполнялось. Этап готов к аппаратной и визуальной приёмке, но не объявляется завершённым пилотом.
