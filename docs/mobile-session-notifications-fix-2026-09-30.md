## Подтверждённая причина блокировки запросов

Ошибка воспроизведена в подписанном release APK 0.1.47 на Android-эмуляторе с Hermes и существующей сессией. Проверка в `httpClient.ts` получала undefined в полях объекта захваченной сессии, созданного с await внутри литерала. Текущий владелец при этом был строкой, поколение сессии оставалось 0. Из-за этого запросы bootstrap, notifications и другие завершались StaleAuthResponseError ещё до нормальной обработки данных. Обычные JS-тесты проблему не воспроизводили.

Захват владельца и поколения заменён отдельными скалярными переменными. Защита от ответов предыдущего пользователя сохранена. После изменения release APK на том же эмуляторе успешно получает bootstrap, заявки, работы, уведомления и отчёты; сервер фиксирует HTTP 200. Точный дефект компилятора/движка отдельно не локализован.

## Push

В серверных данных обнаружена отправка уведомлений на ранее зарегистрированное устройство KENSHI Armor C1s. Worker теперь получает уникальные действующие токены всех активных сессий учётной записи на момент отправки. Ошибка одного устройства не прерывает попытку доставки другим. Отозванные и истёкшие сессии исключаются. При отсутствии устройств уведомление ожидает синхронизации.

Android-фоновая задача разбирает вложенный Expo payload, включая dataString. Локальное уведомление показывается до ожидания синхронизации. Используется notificationId как стабильный идентификатор уведомления.

Worker обновлён отдельно от API и базы. Новый образ: `patrol360-worker:push-fix-20260930`, digest `sha256:65e824946d9a3625bc6e28c1ffb3c0e1fc158243801976e00404d833c4cfaf22`. Предыдущий образ сохранён как `patrol360-worker:before-push-fix-20260930`. Запуск подтверждён журналом Application started.
