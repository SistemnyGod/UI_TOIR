# Отправка отчёта после офлайна — 0.1.51

Дата: 18.10.2026. Изменения ограничены мобильным приложением. Сервер, схема БД и рабочие данные вручную не изменялись.

## Реализовано

- Компактное окно показывает отправку, получение сервером, сохранение до появления сети или необходимость действий пользователя. Закрытие окна не отменяет отправку. Успех появляется только по сохранённому подтверждению сервера.
- После подтверждения доступна кнопка «Готово», даже если ещё выполняется очистка локальных медиа. Автоматический уход со страницы заменён явным действием пользователя.
- Ручная отправка выбранного отчёта получает приоритет между операциями обычной очереди. Текущий HTTP-запрос и запись SQLite не прерываются; порядок зависимых команд сохраняется.
- После приоритетного прохода обычная очередь заново читает доступную команду. Это предотвращает повтор уже принятой команды и обход Retry-After из устаревшего списка.
- При восстановлении потерянного ответа событие доставки отправляется после сохранения квитанции, до очистки файлов. Экраны обновляются также после остановки попытки из-за сети или авторизации.
- При смене сеанса отложенная отправка предыдущего пользователя не запускается.
- При сворачивании приложения выполняется попытка отправить ожидающие операции. Фоновая задача ожидает следующие пакеты вместо запуска продолжения без ожидания. Ограничение — до восьми проходов, проверка бюджета 90 секунд между проходами; текущий запрос не обрывается по этому бюджету.
- Новые циклы опроса статуса и подробные замеры каждого этапа не добавлены. UI обновляется по событиям. Фоновая отправка пользовательских данных не ждёт загрузки диагностических вложений.

Основные файлы: `ReportSendDialog.tsx`, `SubmitReportScreen.tsx`, `reportSubmissionCoordinator.ts`, `prioritySyncQueue.ts`, `syncEngine.ts`, `syncEvents.ts`, `backgroundSyncTask.ts`, `app/_layout.tsx` внутри `mobiel proekt`.
