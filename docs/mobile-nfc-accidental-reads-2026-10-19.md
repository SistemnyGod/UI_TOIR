# Случайное чтение NFC-меток (2026-10-19)

## Проблема

Телефон иногда читает метку дважды или случайно (метка в кармане, телефон положили рядом с точкой). Если в этот момент reader mode приложения выключен, Android сам обрабатывает метку: открывает системное приложение «Метки» или, для URL-записи, браузер. Patrol360 при этом сворачивается.

Раньше reader mode включался только на экране сканирования NFC и снимался при остановке сессии. Окна без reader mode: другие экраны, переход на форму точки после подтверждения (метка ещё у телефона), пауза перед повторным чтением при недочитанной метке, переходы между экранами.

## Что сделано

- **Охранный режим (guard).** Пока пользователь вошёл в приложение, reader mode включён всегда (`enableNfcGuard` в `src/services/nfcService.ts`, управление — `src/services/nfcGuardService.ts`, подключение — `NfcGuardHost` в `app/_layout.tsx`). Вне экрана сканирования метка поглощается приложением: показывается короткая подсказка «Откройте сканирование, чтобы отметить точку» или «Метка уже отмечена» (если эту метку уже отметили в текущем обходе), с лёгкой вибрацией. Метка, которую экран сканирования только что прочитал (до 3 с), поглощается молча.
- **Передача без разрыва.** Сессия сканирования и охранный режим переключаются повторной регистрацией reader mode с другими флагами, без `unregisterTagEvent` между ними. Остановка сессии сканирования возвращает охранный режим; reader mode снимается полностью только при выходе из учётной записи. Пока экран сканирования открыт, охранный режим молчит: метки в паузах между чтениями — это повторы самого экрана.
- **AppState.** В фоне регистрацию не снимаем: нативный модуль сам выключает reader mode при паузе activity и включает при возврате, раньше, чем успел бы JavaScript. При возврате в приложение охранный режим дополнительно перерегистрируется (например, после включения NFC в настройках).
- **Флаги.** Охранный режим: `FLAG_READER_SKIP_NDEF_CHECK` (нужен только факт касания и UID, чтение быстрее) и `FLAG_READER_NO_PLATFORM_SOUNDS` (метка не обрабатывается — системный звук сбивает с толку). Сессия сканирования флаги не меняла: NDEF нужен для сопоставления точек по тексту метки, а системный звук — единственный звуковой сигнал чтения (собственная обратная связь приложения — только вибрация, `src/services/scanFeedback.ts`).
- **Повторы.** Одна и та же метка (совпадение любого кода, в том числе UID) в течение 3 с не обрабатывается повторно (`src/services/nfcReadMemory.ts`). Метка уже отмеченной точки при новом касании на экране сканирования даёт исход «Точка … уже отмечена» без новой записи в outbox (как и раньше, проверка в репозитории).

## Манифест

В `app.config.js` и сгенерированном `AndroidManifest.xml` нет фильтров `NDEF_DISCOVERED` / `TECH_DISCOVERED` / `TAG_DISCOVERED` — приложение не перехватывает метки, когда закрыто. Есть только deep link `VIEW` для схемы `patrol360://`: метка с URI-записью `patrol360://…` при закрытом приложении откроет Patrol360 через этот фильтр (Android запускает `ACTION_VIEW` для URI-записи без обработчика `NDEF_DISCOVERED`). Менять манифест не нужно.

## Ограничения

- Когда приложение закрыто, свёрнуто, экран выключен или заблокирован, reader mode не действует — Android обрабатывает метку сам. Это нельзя исправить в приложении.
- До входа в учётную запись охранный режим выключен.
- Переход между флагами охранного режима и сканирования повторно запускает опрос NFC; что удерживаемая метка снова читается сразу, нужно проверить на устройстве.
- Метка, коснувшаяся телефона в миллисекунды переключения на сканирование, может уйти в охранный режим и молча поглотиться — надо приложить ещё раз.

**Главная мера вне приложения:** не записывать на метки URL/Smart Poster. Для точек маршрута достаточно UID или NDEF-текста (`T`-запись), который читает приложение. Метки с URL-записями нужно перезаписать текстом или очистить — тогда при закрытом приложении Android не откроет браузер.
