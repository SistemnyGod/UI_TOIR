## Правила

- `AssignmentScreen.tsx` и `ResultsScreen.tsx` остаются route-level контейнерами.
- Доменная логика статусов и фильтров уходит в feature-local `assignments/*` и `results/*`.
- Общие UI-примитивы можно выносить только в `shared/ui`, если они не знают про Patrol domain.
- Compatibility exports в `apps/web/src/screens/*` не удаляются без проверки `rg`.
- Новые Patrol-компоненты не добавляются в старый `apps/web/src/components`.

## Выполнено в текущем проходе

- `AssignmentStatusBadge.tsx` вынесен из `AssignmentScreen.tsx`.
- `assignmentUtils.ts` содержит статусные helper-ы и `shouldCreateAssignmentAfterRequest`.
- Старый экспорт `shouldCreateAssignmentAfterRequest` сохранен через `AssignmentScreen.tsx`.

## Следующий безопасный шаг

Выполнено 16 октября: `AssignmentScreen.tsx` сохраняет состояние и команды; `assignments/AssignmentPanels.tsx` содержит выбор сотрудников/маршрутов, историю, активные назначения и настройки смен. ## Результаты обходов — 2026-10-09

Первый этап постепенного рефакторинга отделяет расчёты журнала и загрузку просмотра от интерфейса, сохраняя маршруты, контракты и поведение экранов.

| Файл в `features/patrol/results` | Ответственность |
| --- | --- |
| `ResultsWorkspace.tsx` | Состояние фильтров, составление экрана, действия журнала и открытие просмотра |
| `resultJournalModel.ts` | Группировка точек, длительность, сводка, фильтры и варианты маршрутов; без React и состояния браузера |
| `useResultPreview.ts` | Кэш деталей, объединение повторных запросов, ошибки и повтор загрузки, актуальность сеанса и выбранного обхода, открытие/закрытие вложений |
| `PatrolResultDetails.tsx` | Чтение точек и комментариев обхода |
| `ResultMediaViewer.tsx` | Интерфейс просмотра и навигация по вложениям |
| `ResultMediaContext.tsx` | Детали точки и комментарий сотрудника; сворачиваемая панель просмотра |
| `useAttachmentPreview.ts` | Загрузка одного отображаемого файла и освобождение его object URL |
| `usePhotoViewport.ts` | Масштаб, перемещение и жесты изображения |

Обработчики загрузки деталей и управления вложениями сохраняют ссылки при обычных обновлениях экрана. Изменение пользователя очищает кэш и закрывает просмотр; закрытие фото или новая выборка вложения отменяют применение предыдущего ответа. Поиск и дозагрузка журнала остаются в `hooks/useResultsWorkspace.ts`, отдельно от кэша просмотра.

Прежние именованные экспорты функций из `ResultsWorkspace.tsx` сохранены для совместимости. Новые потребители расчётов должны импортировать `resultJournalModel.ts` напрямую. Структурная проверка ограничивает основной файл текущим объёмом; новые обязанности нужно выделять отдельно.

Следующий этап: выделить панель фильтров и таблицу журнала, затем экспорт и операции архивирования/удаления. Каждый этап проверять отдельно; изменения бизнес-правил и новый дизайн не смешивать с переносом кода.
