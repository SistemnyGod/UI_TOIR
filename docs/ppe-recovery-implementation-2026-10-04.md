# Восстановление СИЗ: реализация и состояние выпуска

Обновлено 05.10.2026. Реализация подготовлена; выпуск на рабочий сервер **не завершён**. Новые выдачи остаются выключенными. Нормативные сведения и утверждения не заменяются тестовыми данными.

## Изменения

- Один серверный проверитель готовности используется в DTO, публикации, подборе норм и блокировке новых выдач. Проверяются область применения, даты, названия требований, единицы, количество, пункт нормы, сроки, действующая номенклатура, утверждения и основания проверки. Обычные требования обязательны по отдельности; явно заданные альтернативы образуют группу выбора.
- Подготовка области, правил, соответствий и публикация доступны при выключенной выдаче с правом `inventory.ppe.norms.manage`. Новый конструктор и все старые HTTP-пути создания фактов блокируются. Повтор уже подтверждённой операции остаётся идемпотентным; просмотр, печать сохранённых документов и возвраты доступны.
- Удалены проверки складского остатка и создание складских движений из операций СИЗ. Поле склада осталось в совместимых контрактах, но не используется для новых операций. Старые ссылки и движения сохраняются.
- UUID `clientDocumentId` обеспечивает повтор создания черновика без дубля. Повтор с другим автором, сотрудником или нормой получает конфликт. Версии документов и ключ подтверждения сохранены.
- Частичный возврат накапливает возвращённое количество и оставляет остаток выданным. Полный возврат и списание записывают историю и даты без складских движений. Архивирование действующей выдачи блокируется; конкурентное изменение проверяет версию карточки.
- Журнал и подготовка норм сохраняют строки, открытый просмотр и прокрутку при обновлении. Владелец репозитория, поколения запросов и проверки состояния формы отбрасывают поздние ответы. Смена пользователя очищает предыдущие данные. Несохранённый ввод не заменяется фоновым ответом.
- Поиск сотрудников выполняется сервером после задержки 300 мс, страницами по 50, выбранный сотрудник восстанавливается по ID. Подтверждённые документы показывают сохранённый снимок.
- Ошибка browser storage отделена от успешного сохранения в БД; потерянный ответ проверяется чтением документа. Повтор PUT, обнаруживший чужое изменение, не объявляет чужой документ сохранённой версией формы.
- Интерфейс показывает причину выключенной выдачи и переход к нормам, прогресс всех 34 наборов, причины по строкам, отдельные количества сопоставлений и утверждений. Три наследованных шаблона доступны для явной привязки владельца и нормы.
- Подготовлен Gotenberg 8.37.0: производственный override использует внутреннюю сеть печати, 1 GiB и 2 CPU без публикации порта. Печать документа до подтверждения не создаёт выдачу.

Новых миграций БД нет. Массовая миграция истории, APK и изменения других модулей в выпуск не включены.

## Выпуск только СИЗ

Рабочая директория содержит ранее начатые изменения обходов и мобильного приложения. Для выпуска восстановлен исходный код фактически установленной версии по манифесту 30.09.2026 и PDB. До наложения СИЗ пересобранный web совпал с рабочим побайтно по всем 32 файлам. Затем наложены только 39 файлов реализации СИЗ. Перечень и SHA-256 находятся в `release-manifest.json`; снимок — `release-source`. Он не меняет Git и не включает посторонние незавершённые изменения.

Сценарий `tools/Publish-PpeRecovery.ps1`:

1. Проверяет SHA снимка и конфигурации выпуска, запускает проверки UI/API и собирает снимок web.
2. Сохраняет предыдущие хешированные web assets для уже открытых вкладок и собирает API/web/Gotenberg.
3. При `-Deploy` повторно проверяет версии образов, создаёт свежую резервную копию, сохраняет старые образы и отпечатки истории.
4. Выполняет `up --no-deps --no-build api web gotenberg`, не обновляет worker/proxy/PostgreSQL и не запускает миграции.
5. Проверяет здоровье, выключенный флаг, изоляцию и лимиты печати, сохранность worker и отпечатки карточек/строк/шаблонов/движений.

Корневой `.env` содержит только настройки сети. Сценарий повторно использует существующие настройки и секрет PostgreSQL в памяти процесса, не печатает пароль и не создаёт новый файл с секретами. Compose проверен с синтетическим значением пароля; это подтверждает синтаксис конфигурации, а не рабочее подключение.

Команды из корня проекта, после восстановления возможности разрешённого запуска:

```powershell
./tools/Publish-PpeRecovery.ps1          # сборки и проверки, без изменения сервера
./tools/Publish-PpeRecovery.ps1 -Deploy -SkipBuild  # проверенные образы, выдача OFF
```

`-SkipBuild` нельзя применять к старому предварительному образу: проверка revision остановит выпуск. На момент отчёта финальные образы **ещё не собраны** и рабочие контейнеры не обновлены.

## Незавершённые шаги и откат

Автоматическая проверка разрешений остановила Vite/Vitest, Docker build и браузер: сначала тайм-ауты, затем `stream disconnected before completion: error sending request`. Пользователь повторно разрешил выпуск с выключенной выдачей, но повтор проверки снова завершился ошибкой сервиса. Инструмент сообщил, что это сбой проверки, а не признание действия небезопасным. Обход разрешений не выполнялся.

После восстановления инструмента нужно закончить финальные сборки и браузерную проверку, выпустить API/web/печать с выдачей OFF, проверить рабочую печать и отпечатки истории. Затем требуется человеческая приёмка 34 наборов, 79 связей и недостающих нормативных сведений, физическая печать и новая резервная копия перед включением. Только после этого можно включать выдачу и проверять фактически выдаваемый комплект.

При сбое сохранять OFF, документы и журналы. Прежние образы можно вернуть только после оценки совместимости с сохранёнными данными. Не запускать автоматический Down и не удалять таблицы. Запуск всех 34 наборов пока не считается завершённым.
