# Интерфейс СИЗ по согласованным референсам

14.09.2026. Рабочая копия поверх `473f839cae7b790510d149bace9ee953b297f819`, с незакоммиченными изменениями, включая ранее существовавшие. Worktree 556a и рабочее развёртывание не изменялись.

## Реализовано

- Журнал выдачи: поиск по сотруднику/табельному, подразделение, период, статусы, выбор столбцов, CSV, страницы по 10/25/50/100. Состав документа открывается в модальном окне. История фильтрует журнал по сотруднику; черновик открывается в мастере.
- Четыре шага: сотрудник и характеристики → проверка → комплект СИЗ → документы. Используются существующие API сохранения, валидации, подтверждения и права доступа.
- Подбор утверждённых товаров плитками в модальном окне, поиск, категории по группам нормы. Редактирование даты, срока носки с быстрыми значениями, количества, цены и размера. Удаление позиции, полный комплект, исключения с причиной.
- Сохранение, поиск и переименование шаблонов, добавление или замена комплекта с подтверждением. Перед применением проверяется актуальность утверждённых соответствий.
- Две печатные формы: личная карточка с двумя ровными блоками реквизитов и четырьмя нормативными колонками; альбомная выдача/возврат/подписи. У второй убраны блок сотрудника и дата формирования над таблицей. У черновика сохраняется маркировка планового документа.
- HTML-предпросмотр состава, выбор документа, масштаб, разворот, существующие Word/PDF endpoints. Точная пагинация и печать идут через серверный PDF.
- На телефоне журнал превращается в карточки, формы и модальные окна адаптируются. На ПК сохраняются таблицы и широкая компоновка. Общая навигация проекта сохранена.

## Исправления корректности

Выбранный срок носки добавлен в JSON-снимок документа и применяется при подтверждении к DueAt. Старые снимки без поля используют срок нормы; миграция БД не требуется. Запросы списка обогащены подразделением/табельным и признаком просрочки одним пакетным запросом фактов.

Исправлено открытие документа из журнала при повторном запуске эффекта и последующей перезагрузке. PDF прежней версии очищается после изменения состава; поздний ответ не подменяет актуальный предпросмотр. Шаблон не переносит размеры, даты и причины исключений другого сотрудника.

## Отличия от картинок и незавершённая приёмка

1. API не предоставляет фото и отдельный ГОСТ для карточек подборщика. Использованы честные иконки-заглушки и подписи. Режим группировки ГОСТ показывает отсутствие данных, а не вымышленные нормативы. Для фактической сортировки по ГОСТ нужно расширение каталога.
2. Шаблоны локальны для браузера и аккаунта, не общая серверная библиотека. Панель шаблонов реализована модальным окном, не постоянной колонкой.
3. Журнал пока получает последние 200 документов по существующему API. Пагинация и фильтры действуют на этот набор. Для полной многолетней истории нужны серверные фильтры/пагинация; ограничение явно подписано в интерфейсе.
4. В модальном составе показаны сохранённые позиции и сроки. Текущие возвраты/списания по каждой позиции остаются в существующей личной карточке; не выводится ложное состояние по одному лишь сроку.
5. Печать каждого документа доступна отдельно. Объединённая печать обеих форм одним PDF пока не реализована. Количество копий задаётся в системном диалоге.
6. Локальный стенд использует синтетический API в памяти и отвечает явной ошибкой на PDF, поскольку не запускает конвертер. Печатные DOCX проверены отдельно через Word; это не приёмка production Gotenberg и принтера.
7. Фотографии, общая библиотека шаблонов, полная история, реальная печать через production-конвертер и окончательная приёмка на физическом телефоне остаются следующими работами. Совпадение с референсами не заявляется пиксельным.

## Превью и воспроизведение

[Открыть локальный журнал](http://127.0.0.1:5291/#inventory-ppe). Стенд слушает только loopback, не проксирует рабочий сервер. Синтетические изменения исчезают при перезапуске; шаблоны остаются в localStorage этого origin.

Из корня: `npm --prefix apps/web run build`, затем `node tools/ppe-ui-preview.mjs`.

Основные исходники: `apps/web/src/features/inventory/ppe/`, `PpeIssueDocumentConstructor.tsx`, `styles/ppe-reference.css`, `styles/ppe-journal.css`. Серверные изменения: `PpeIssueDocumentContracts.cs`, `EfInventoryWorkflowService.IssueDocuments.cs`, `PpeIssueDocumentDocxBuilder*.cs`.
