# Удаление выбора исполнителя телефона

Дата: 28 сентября 2026 года.

## Изменённый сценарий

- На главной и в списке заявок больше нет отдельного выбора сотрудника телефона. В профиле показывается аккаунт приложения.
- Текущий обход определяется только явно выбранным назначением. Исполнитель берётся из назначения. Отсутствие текущего назначения не выбирает старый обход автоматически.
- Принятие свободной заявки сохраняет обязательный выбор допустимого сотрудника внутри заявки. Этот выбор не становится глобальной настройкой. Поле не переносится между разными карточками заявок.
- При переключении одного сотрудника применяется существующая атомарная операция с её проверками и зависимостями. Если выбран обход другого сотрудника, сохраняется обычная проверка запуска и конфликта его назначения. Выбор Б не переназначает и не архивирует обход А.
- В работах — «Активные» и «История» для доступных аккаунту записей. Отдельный фильтр по исполнителю телефона удалён. SQL ограничивает страницу после фильтра состояния. История обновляет серверный раздел истории.
- Исполнитель новой работы, замечания или участия остаётся полем соответствующей операции. При единственном доступном сотруднике он подставляется автоматически; при нескольких требуется явный выбор в форме.

## Сохранность и совместимость

Публичный контекст телефона содержит только assignmentId. Старое employee_id в таблице контекста не читается и больше не определяет поведение; при записи контекста записывается NULL. Колонка сохранена для совместимости установленной SQLite, старые миграции не переписывались.

Черновики привязаны к аккаунту, контуру, виду формы и объекту; новая форма получает независимый ключ. Сотрудник сохраняется внутри данных формы. Старые employee_id в таблице черновиков остаются ключами хранения, а не выбором исполнителя. Один черновик восстанавливается сразу; несколько показываются для явного выбора без слияния и удаления текстов. Можно открыть новую форму, не перезаписывая старые. Ошибка чтения черновика не создаёт замену поверх повреждённых данных.

Перед применением формы проверяется зафиксированная сессия. При смене фокуса устаревшее открытие черновика отклоняется. Работа, очередь и удаление выбранного черновика продолжают использовать существующие транзакции.

Серверные назначения, полномочия аккаунта и обязательность сотрудника в командах не менялись. Посещение раздела работ больше не выбирает исполнителя и не очищает текущий обход.

- Vitest: 154 теста, 55 файлов.
- TypeScript, линтер, кодировка — без ошибок.
- Проверка diff на ошибки пробелов — без ошибок.

Регрессии охватывают импорт старого контекста, отсутствие выбора при сохранённом только сотруднике, изоляцию аккаунтов, запуск и переключение, условное очищение после доставки, поздние квитанции, доступ ко всем старым черновикам, независимость ключа формы от поля сотрудника, страницы активных работ и истории разных сотрудников. Тесты репозиториев черновиков, списков и навигационного контекста используют SQLite в памяти.

Журнал: `output/mobile-ui-remove-device-performer-verify.log`.

Новый APK в этом шаге не собирался. Визуальная проверка изменённых экранов на эмуляторе и приёмка на физических телефонах не выполнялись. Существующий APK 0.1.33 из предыдущего этапа этих изменений не содержит.
