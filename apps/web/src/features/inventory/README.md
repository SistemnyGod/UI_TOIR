# Inventory

Модуль учёта: сотрудники, номенклатура, СИЗ, выдача и возвраты, отчёты.
Публичные экраны остаются в корне feature; экран координирует сценарий,
а независимые формы и операции размещаются в соответствующем подразделе.

`InventoryScreen.tsx` выбирает рабочий или демонстрационный режим.
`InventoryWorkspace.tsx` хранит загрузку общих данных и подключает каждый
подраздел через `React.lazy`; демонстрационный репозиторий доступен только
через `InventoryMockWorkspace.tsx`. Не возвращайте общий manual chunk для
всего `features/inventory`: он объединит эти границы загрузки.
Изолированные старые правила вынесены в `styles/legacy-global.css` и
подключаются перед остальными стилями модуля для сохранения их порядка.

## СИЗ

| Область | Точка входа | Ответственность |
| --- | --- | --- |
| Проверка норм | `PpeNormSetsAdmin.tsx` | Прогресс, фильтры готовности, раскрытие наборов и публикация |
| Загрузка норм | `ppe/norms/usePpeNormWorkspace.ts` | Общий индекс, серверный поиск, ленивый каталог, импорт и сопоставления |
| Строки нормы | `ppe/norms/NormSetDetails.tsx` | Категории, поиск требований, сопоставленные и утверждённые товары |
| Изменение норм | `ppe/norms/NormEditors.tsx` | Область применения, правила строки и явное утверждение соответствия |
| Операции редакторов | `ppe/norms/useNormMutation.ts` | Защита от повторного сохранения и ответов закрытого редактора |
| Подбор товара | `ppe/norms/NormCatalogSelector.tsx` | Рекомендации и ручной поиск; подбор не утверждает товар |
| Журнал | `ppe/PpeIssueJournal.tsx` | Навигация, настройки столбцов, пагинация и доступность действий |
| Данные журнала | `ppe/journal/usePpeIssueJournal.ts` | Независимые загрузки доступности, списка, документа и экспорта |
| Представление журнала | `ppe/journal/JournalFilters.tsx`, `JournalTable.tsx`, `JournalDocumentModal.tsx` | Фильтры, адаптивная таблица и просмотр снимка документа |
| Настройки журнала | `ppe/journal/journalColumns.ts` | Разрешённые столбцы, безопасное чтение предпочтений пользователя |
| Конструктор | `PpeIssueDocumentConstructor.tsx` | Владелец формы, черновик, версии, подтверждение и печать |
| Этапы конструктора | `ppe/DocumentEmployee.tsx`, `DocumentKit.tsx`, `DocumentReview.tsx`, `DocumentNavigation.tsx` | Формы, комплект, документы, навигация и история |

Общие правила сохранения находятся в `documentPersistence.ts`,
`documentDraft.ts` и `documentStorage.ts`; скачивание файлов — в
`downloadPpeFile.ts`. Вызовы API проходят через `InventoryRepository`.
UI не меняет складские остатки и не обходит серверную блокировку выдачи.

Прежний мастер и его недостижимые модалки удалены. Старые личные карточки
открываются из журнала через «Нормы и личные карточки»; просмотр, возврат,
списание и печать сохраняются. Подбор товаров и выдача используют текущую
подготовку норм и конструктор. `LegacyIssueDraftNotice` позволяет скачать
сохранившийся черновик прежнего мастера только для его владельца.

## Границы состояния

- Поиск норм не перезагружает общий индекс готовности. Каталог загружается
  при открытии набора; одновременные открытия используют один запрос.
- Фоновая загрузка сохраняет строки, открытый документ и несохранённые поля.
  Изменение пользователя или репозитория инвалидирует предыдущие ответы.
- Предпочтения столбцов привязаны к пользователю. Ошибка browser storage
  не считается ошибкой сохранения документа в БД.
- Редакторы норм отправляют ожидаемую версию. Ответ с меньшей версией
  не заменяет уже полученную версию набора.
- Шаблоны, правила выдачи и фактическое подтверждение проверяет сервер;
  формы представляют причины блокировки и не подтверждают связи автоматически.

## Проверка и выпуск

Из `apps/web`: `npm run typecheck`, `npm run test:unit -- ppe`, `npm run build`.
Регрессии поиска, фонового обновления, экспорта и смены владельца покрыты
`src/__tests__/ppeJournal.test.tsx` и `ppeNormWorkspace.component.test.tsx`.
Проверки сохранения и подтверждения находятся в `ppeRecovery.component.test.tsx`.

Стили СИЗ разделены по сценариям в `styles/ppe-*.css` и `ppeNormRecovery.css`.
Общие исторические стили inventory остаются совместимыми с другими экранами.
Новые runtime-файлы включаются в явный список `tools/apply-ppe-release-overlay.py`;
структуризация сама по себе не запускает публикацию и не включает выдачу.

Окна сотрудников учёта находятся в `employees/`: редактор, импорт/архивирование и `EmployeePpeHistoryDialog`, общий для сотрудников и выдачи. Они используют общую оболочку `ModalShell`; ошибка операции принадлежит форме, успешное закрытие — рабочему экрану. `PpeMovementHistoryPanel` загружает серверные страницы и разделяет состояние по сотруднику/предмету.

Окна под запись разделены на выдачу (`CustodyIssueDialog`), справочник предметов (`CustodyItemDialog`), операции по строке (`CustodyActionDialog`) и просмотр (`custodyDrawer`). `useCustodyCommand` владеет состоянием формы; `useCustodyRepositoryActions` различает результат записи и обновления и отбрасывает поздние чтения. Просмотр события СИЗ — `ppe/PpeHistoryEventDialog`; он использует общую оболочку. При отдельном выпуске необходимо сверять состав новых frontend-зависимостей: исторический PPE-overlay от 04.10 не является полным пакетом текущей унификации UI.
