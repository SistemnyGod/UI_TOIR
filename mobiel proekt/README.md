# Мобильное приложение сотрудников

В этой папке расположен проект мобильного приложения Patrol360 для сотрудников обхода и учета работ.

Основное ТЗ: [`../docs/mobile-app-technical-requirements.md`](../docs/mobile-app-technical-requirements.md).

## Решения по проекту

- Проект мобильного приложения размещается отдельно от web/backend кода.
- Целевая платформа первого релиза: Android.
- Стек: React Native + Expo + TypeScript.
- Пилотное устройство: Kenshi Armor C1s.
- Первые маршруты пилота: `Обход печей`, `Помол`.
- Для NFC и production-проверок используется dev/release build, не Expo Go.

## Команды разработки

```powershell
npm install
npm run verify
npm run start
```

`verify` запускает mobile policy/contract tests, проверку кодировки, TypeScript и ESLint.

## Стили и темы

Цвета берутся только из темы, чтобы светлая и тёмная темы не расходились:

- палитры `lightColors`/`darkColors` — в `src/ui/atomTheme.ts`, отступы, радиусы и размеры шрифта — в `src/ui/tokens.ts`;
- стили экрана объявляются фабрикой `createThemedStyles((colors, { spacing, radius, fontSize }) => ({ ... }))` на уровне модуля и подключаются через `useThemedStyles(createStyles)`; лист создаётся один раз на каждую тему;
- постоянные цвета бренда и иллюстраций (логотип, белый текст на синем блоке, фон входа, анимация сканирования) — в `src/ui/brandPalette.ts`, градиенты — в `src/ui/GradientFill.tsx`.

ESLint запрещает литералы `#hex`, `rgb()`/`rgba()` и `hsl()` в `src/` и `app/` вне этих трёх модулей. Новый цвет добавляется токеном в обе палитры `atomTheme.ts` или, если он не зависит от темы, именованной константой в `brandPalette.ts`. В `brandPalette.ts` раздел `fixedLight` перечисляет старые светлые цвета, которые пока не меняются в тёмной теме.

## Голосовой ввод описания точки

Кнопка микрофона в поле «Результат осмотра» диктует русский текст и добавляет его в конец описания. Используется `expo-speech-recognition` (Android `SpeechRecognizer`):

- если на телефоне установлен офлайн-пакет русского языка (Speech Services by Google), распознавание идёт на устройстве и работает без интернета;
- без пакета используется сетевое распознавание, и только при наличии сети; без сети показывается подсказка установить пакет;
- отказ в доступе к микрофону и отсутствие службы распознавания тоже показываются подсказкой, текст можно ввести с клавиатуры.

Модуль нативный: после обновления нужна новая сборка APK (`expo prebuild` выполняют скрипты сборки). Плагин добавляет разрешение `RECORD_AUDIO`, оно запрашивается только при нажатии на микрофон. В APK, собранном до появления модуля, форма точки открывается, а микрофон показывает «Голосовой ввод недоступен».

## Сборка APK

Android/Expo tooling нестабильно работает, когда native Android-проект генерируется в пути с кириллицей или пробелами. Поэтому локальная сборка APK выполняется через скрипт, который создает временную ASCII-папку, запускает `expo prebuild`, применяет совместимый Gradle resolver и копирует APK обратно в `build-output`.

Release-сборка требует явного контура и release-ключа. Рекомендуемый локальный запуск:

```powershell
$env:PATROL360_ENVIRONMENT = 'local-enterprise'
.\scripts\build-release-apk.ps1
```

Основной адрес контура `local-enterprise`: `https://192.168.2.194` (порт 443). APK включает публичный сертификат локального Root CA из `infra/docker/certs/patrol360.rootCA.crt`. Серверный сертификат должен содержать IP `192.168.2.194` в SAN. Старый HTTP-адрес `http://192.168.2.194:5173` поддерживается для ранее настроенных клиентов; операция, начатая по HTTPS, не переходит на HTTP при ошибке сертификата.

Для телефона и сервера должны быть доступны друг другу адреса локальной сети; на Windows нужно разрешить входящий TCP 443 из `192.168.2.0/24` через `infra/scripts/allow-patrol360-mobile-lan.ps1`. Проверка: `https://192.168.2.194/api/v1/mobile/health`. Ожидаются `status: ok`, `syncProtocolVersion: 1.0` и `contourId: patrol360-local-enterprise`.

При наличии внешнего сервера можно встроить второй разрешённый HTTPS-адрес того же контура:

```powershell
$env:PATROL360_ENVIRONMENT = 'local-enterprise'
$env:PATROL360_PUBLIC_API_URL = 'https://<белый-ip>'
.\scripts\build-release-apk.ps1
```

Также адрес можно передать параметром `-PublicApiBaseUrl`. Приложение сначала проверяет локальный адрес, затем резервный. Публиковать mobile API в Интернет по незашифрованному HTTP нельзя; для белого IP требуется HTTPS, VPN либо другой защищённый канал. Проброс порта и правила внешнего firewall настраиваются отдельно от APK.

По умолчанию оба скрипта собирают универсальный APK с архитектурами `armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64` для 32- и 64-битных устройств. Минимальная версия текущего приложения — Android 7.0 (API 24). Для сборки под одну архитектуру можно передать, например, `-ReactNativeArchitectures arm64-v8a`.

Wrapper автоматически выбирает доступную DPAPI-копию существующего ключа и сверяет сертификат с публичным отпечатком из `release-signing.json`. Проверить ключ без сборки:

```powershell
.\scripts\build-release-apk.ps1 -ValidateOnly
```

Для существующего ключа создать резервную DPAPI-копию уровня компьютера:

```powershell
.\scripts\backup-release-signing.ps1
```

Signing metadata и JKS находятся в ignored-каталоге `secrets` и не коммитятся. `create-release-keystore.ps1` блокирует случайное создание нового сертификата, если сертификат приложения уже закреплён.

Результат:

- `build-output/patrol360-mobile-release.apk`

Для отладочной standalone-сборки:

```powershell
npm run build:android:debug
```

Результат:

- `build-output/patrol360-mobile-debug.apk`

Подробный порядок хранения, проверки и восстановления релизного ключа описан в [`../docs/mobile-release-signing.md`](../docs/mobile-release-signing.md).

После release-сборки скрипт выполняет zipalign, подписывает APK и проверяет подпись. Перед передачей зафиксируйте package/version, SHA-256 и certificate digest.

Внешний резервный адрес включается только через `PATROL360_PUBLIC_API_URL`; заранее заданный неработающий HTTP-адрес удалён.
